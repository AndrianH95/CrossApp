# CrossApp — Консольний та Веб-Застосунок на .NET

Лабораторний практикум із дисципліни розробки програмного забезпечення на платформі .NET. Проєкт `CrossApp` є модульним застосунком, що демонструє еволюцію від баз коду консольного CLI до повноцінного **REST API (Minimal API)** із Clean Architecture, валідацією та документацією OpenAPI/Scalar.

---

## 📋 Огляд лабораторних робіт

### **Лабораторні роботи №1–3: Основи ООП та Консольний Інтерфейс (CLI)**
* **ЛР №1**: Створення базової структури рішення `CrossApp` та консольного проєкту `Cli`.
* **ЛР №2**: Проєктування доменних моделей (`Product`) та використання принципів інкапсуляції.
* **ЛР №3**: Реалізація консольних команд для взаємодії з користувачем та обробки вхідних даних.

### **Лабораторні роботи №4–6: Архітектура, Абстракції та Файлові Операції**
* **ЛР №4**: Виділення шару ядра `Core` та впровадження абстракцій (`ICatalogStore`, `ICatalogImporter`).
* **ЛР №5**: Реалізація імпорту/експорту даних товарів із файлів (CSV / JSON) та обробки винятків.
* **ЛР №6**: Застосування шаблонів проєктування (Inversion of Control, Dependency Injection) та конфігурація `AppOptions`.

### **Лабораторні роботи №7–9: Розширений Функціонал та Тестування**
* **ЛР №7**: Додавання звітів (`Reports`) та розширених фільтрів для каталогу товарів.
* **ЛР №8**: Впровадження подій (Events) та асоційованої логіки сповіщень.
* **ЛР №9**: Юніт-тестування та верифікація бізнес-логіки ядра.

### **Лабораторна робота №10: Інтеграція REST API (Minimal API & OpenAPI)**
* Створення та налаштування REST-сервісу у проєкті `Api` на базі **Minimal API**[cite: 1, 3].
* Дотримання Clean Architecture: винесення DTO (`ProductDto`), реквестів (`SaveProductRequest`) та мапінгу у проєкт `Api.Contracts`[cite: 2].
* Реалізація повного спектра CRUD-операцій (`GET`, `POST`, `PUT`, `DELETE`) для каталогу товарів (`/api/products`).
* Впровадження ручної валідації запитів із поверненням помилок у стандарті **RFC 9457 (ProblemDetails / ValidationProblem)**[cite: 2].
* Системний ендпоїнт перевірки стану `/health`.
* Інтеграція сучасного інтерфейсу документації **Scalar UI (OpenAPI 3.1)**[cite: 1, 2, 5].

## 🛠 Технологічний стек

* **Платформа**: .NET 9 / C#
* **Архітектурний паттерн**: Clean Architecture / Layered Architecture[cite: 2]
* **Веб-фреймворк**: ASP.NET Core Minimal API[cite: 1]
* **Документація**: OpenAPI / Scalar (`Scalar.AspNetCore`)[cite: 1, 5]
* **Формат помилок**: RFC 9457 Problem Details[cite: 2]
