## 🏗️ Структура рішення
* `src/Cli/` — Консольний застосунок (точка входу, Composition Root, top-level `await`, обробка сигналів скасування та підкоманд звітів).
* `src/Core/` — Бібліотека класів (доменна модель, `DomainException`, інтерфейси імпортерів, сховища, сервіси, події, звіти `ReportService`).
* `tests/Core.Tests/` — Проєкт модульних тестів (xUnit) для перевірки доменної логіки та асинхронних сценаріїв.
* `data/` — Тестові файли даних (`sample.csv`, `catalog.json`).
* `logs/` — Каталог для системних логів (`app.log`).

#### 🛡️ Інваріанти доменної моделі:
1. Обов'язкові ключі та назви (`Id`, `SKU`, `Name`) не можуть бути порожніми чи складатися з пробілів (`ArgumentException`).
2. Початковий залишок товару не може бути від'ємним (`ArgumentOutOfRangeException`).
3. Кількість приходу або видачі має бути суворо більшою за нуль (`ArgumentOutOfRangeException`).
4. Неможливо видати зі складу більшу кількість товару, ніж є в наявності (`InvalidOperationException`).

* Розширено початковий набір даних (`SampleData`) до 16 записів з різними одиницями виміру та дефіцитними позиціями.

#### ⏳ Особливості відкладеного виконання LINQ:
Оператори фільтрації та сортування (`Where`, `Select`, `OrderBy`) не виконуються в момент їх оголошення, а ініціюють обробку даних лише під час виклику завершальних операторів (наприклад, `Count()` або `ToList()`). Через це модифікація джерела даних після створення змінної запиту, але до його виконання, безпосередньо впливає на результат. Матеріалізація результату через `ToList()` створює статичний знімок даних (snapshot), захищаючи його від подальших змін у джерелі.
